# Бот-уведомитель о подписчиках канала (Render + Supabase)

## Как это работает
1. Пользователь пишет боту `/start` — бот присылает в ответ его Telegram ID
   (в копируемом формате).
2. Пользователь пересылает боту любое сообщение **из канала**, либо
   присылает ссылку вида `https://t.me/username` (для публичных каналов).
3. Бот проверяет, что сам состоит в этом канале как администратор,
   и сохраняет в Supabase запись «этому пользователю — уведомления по
   этому каналу». Если бот не добавлен в канал (или не администратор) —
   присылает пошаговую инструкцию, что именно поправить.
4. Когда в канал вступает новый участник, бот смотрит в Supabase, кто
   подписан на уведомления именно по этому каналу, и рассылает им
   сообщение с именем, юзернеймом и ID нового подписчика.

Привязки хранятся в Supabase (внешняя БД), а не на диске Render —
иначе они бы терялись при каждом "усыплении" бесплатного сервиса.

Все сообщения бота используют HTML-форматирование (жирный текст,
моноширинный шрифт для ID и ссылок); пользовательские данные (названия
каналов, имена) экранируются перед вставкой, чтобы случайные символы
`<`, `>`, `&` в них не ломали разметку.

## Админские команды (только для ADMIN_ID)

- **`/broadcast`** — бот спросит сообщение (кнопка «Отмена»), затем
  разошлёт его всем, кто хоть раз писал боту `/start`. Подойдёт текст,
  фото, видео, голосовое — что угодно.
- **`/referrals`** — открывает меню реферальных ссылок:
  - ➕ Создать реферальную ссылку — по названию строит ссылку вида
    `https://t.me/имя_бота?start=ref_название`
  - 🗑 Удалить реферальную ссылку
  - 📈 Статистика по одной ссылке
  - 📊 Статистика по всем ссылкам
  - 🚪 Выход

Всем, кто не является `ADMIN_ID`, эти команды не отвечают вообще —
даже намёка на их существование не будет.

## Шаг 1. Telegram
1. Создайте бота через [@BotFather](https://t.me/BotFather), получите `BOT_TOKEN`.
2. Добавьте бота во все нужные каналы как **администратора**. Конкретные
   права роли значения не имеют — важен сам факт статуса администратора,
   без него Telegram не присылает боту события о новых подписчиках.
3. Узнайте свой Telegram ID (например, через `/start` у любого из ваших
   ботов) — понадобится для `ADMIN_ID`.

## Шаг 2. Supabase
1. Зарегистрируйтесь на [supabase.com](https://supabase.com), создайте
   организацию и проект (бесплатный план).
2. Создайте три таблицы через SQL Editor, без RLS:
   ```sql
   create table subscriptions (
     id bigint generated always as identity primary key,
     channel_id bigint not null,
     user_id bigint not null
   );

   create table bot_users (
     id bigint generated always as identity primary key,
     bot_name text not null,
     user_id bigint not null,
     referral_code text,
     created_at timestamptz not null default now(),
     unique (bot_name, user_id)
   );

   create table referral_links (
     id bigint generated always as identity primary key,
     bot_name text not null,
     code text not null,
     created_at timestamptz not null default now(),
     unique (bot_name, code)
   );
   ```
   Таблица `bot_users` общая для обоих ваших ботов (бот-уведомитель и
   бот-повторитель) — их записи различаются полем `bot_name`
   (`notify` / `whisper`), поэтому одну и ту же базу можно использовать
   для обоих.
3. В разделе **Project Settings → API Keys**, вкладка "Publishable and
   secret API keys", скопируйте:
   - **Project URL** → это будет `SUPABASE_URL`
   - **Secret key** (`sb_secret_...`) → это будет `SUPABASE_KEY`
     (секретный, никому не показывайте и не публикуйте в открытом
     репозитории)

## Шаг 3. Загрузка кода на GitHub
Создайте репозиторий и залейте туда файлы:
- `notify_bot.py`
- `requirements.txt`
- `render.yaml` (не обязателен при ручной настройке через Web Service)

## Шаг 4. Деплой на Render
1. Зайдите на [render.com](https://render.com), войдите/зарегистрируйтесь.
2. **New +** → **Web Service** → выберите репозиторий.
3. Заполните:
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `python notify_bot.py`
   - **Instance Type**: Free
4. Добавьте переменные окружения (Environment Variables):
   - `BOT_TOKEN` — токен бота
   - `SUPABASE_URL` — Project URL из Supabase
   - `SUPABASE_KEY` — Secret key из Supabase
   - `WEBHOOK_HOST` — публичный URL сервиса, вида
     `https://ИМЯ-СЕРВИСА.onrender.com`
   - `WEBHOOK_SECRET` — произвольная случайная строка (защита вебхука)
   - `ADMIN_ID` — ваш Telegram ID (необязательно, но без него
     `/broadcast` и `/referrals` не будут работать ни для кого)
   - `PYTHON_VERSION` — `3.11.9` (более новые версии Python могут не
     иметь готовых собранных пакетов для некоторых зависимостей
     `aiogram`, из-за чего сборка падает на Render)
5. Нажмите **Deploy web service**.

⚠️ **`WEBHOOK_HOST` должен начинаться с `https://` и не содержать
случайных пробелов или переносов строк** — при вставке в поле на Render
иногда добавляется невидимый перенос строки, из-за которого Telegram
возвращает ошибку `Bad webhook`.

⚠️ **Точный адрес сервиса может отличаться** от того, что вы вписали
заранее в `WEBHOOK_HOST` (Render иногда добавляет случайные символы к
имени, если оно частично занято). После первого деплоя сверьте адрес
наверху страницы сервиса и при необходимости поправьте переменную и
передеплойте.

## Шаг 5. Проверка
1. Откройте `https://ИМЯ-СЕРВИСА.onrender.com/` в браузере — должно
   вернуться `ok`.
2. Напишите боту `/start` — он пришлёт ваш Telegram ID.
3. Перешлите боту сообщение из канала (или пришлите ссылку на публичный
   канал) — бот подтвердит подписку либо подскажет, что поправить в
   правах.
4. Подпишитесь на этот канал тестовым аккаунтом — должно прийти
   уведомление.
5. Если вы `ADMIN_ID` — попробуйте `/broadcast` и `/referrals`.

## Ограничения, о которых нужно знать
- **Приватные каналы:** ссылка `t.me/username` работает только для
  публичных каналов. Для приватных — только пересылка сообщения из
  канала.
- **Пересылка с "защищённым содержимым":** если в канале включена
  настройка "Защита контента" (запрет пересылки), переслать сообщение
  из него не получится — придётся временно её отключить, подключить
  канал к боту, затем включить обратно.
- **UptimeRobot не требуется.** Бот работает через webhook и сам
  "просыпается" при поступлении события от Telegram — не нужно держать
  его искусственно разбуженным. После долгого простоя первый ответ
  может прийти с задержкой 30-60 секунд.
- **`/broadcast` рассылает не мгновенно** — между отправками каждому
  пользователю есть небольшая пауза (0.05 сек), чтобы не упереться в
  лимиты Telegram на количество сообщений в секунду. При большой базе
  пользователей рассылка может занять заметное время.

## Важно про бесплатный план Render
Бесплатные веб-сервисы на Render "засыпают" после ~15 минут без
входящих запросов и "просыпаются" 30-60 секунд при следующем запросе.
Поскольку этот бот не требует постоянной доступности (события редкие),
он почти не расходует месячную квоту в 750 бесплатных часов инстанса.
